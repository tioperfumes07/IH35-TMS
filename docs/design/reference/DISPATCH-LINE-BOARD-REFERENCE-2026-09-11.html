Design contract — Dispatch › Truck Line (owner request 2026-09-11 16:30–16:50 CT) · v3

Owner, verbatim: “a new kanban format design page almost the same as it is here. but it will be instead of dragging the truck box, it will be like a line map of a truck … double click on that rows box … it shows the line and that it is currently at dispatched, we then click on at pick up etc.” · “we are missing in the design the status names on top.” · “we need to have after in transit one for Other, and in that one, a drop down list of reasons so it can be visible.” · “colors, i want this a little more lively and happy” → then “nevermind, remove these colors. in the line maybe green, red if any issues etc.” — the second ruling stands.

Name

Colors (owner 16:55 CT): app palette unchanged — navy, greys, the Load Costs tokens. The LINE is the only colored element: green for every station reached, red for an issue (Other/exception, late appointment, no ping). No per-station colors.

The four existing views are Kanban, List, Round Trips, Trip Pairing. This one is Truck Line — one line per truck. (Alternates if the owner prefers: “Status Line”, “Progress Board”. The name must be plain English, one idea, no machine words.) It is the 5th segment in the same control; nothing removed.

What it is

One row per in-service truck, no dragging. Station names are the column header, each in its own color; the row's line fills with the same colors as far as the load has reached; the next station is the only clickable advance; clicking it stamps the real event on the real row through the existing service. Double-clicking the truck box opens the load page (Accounting › Load costs › <load>). A truck with no load keeps its row (grey rail, “Book Load on Txxx”).

The reason catalog (one catalog, additive, plain English — same pattern as catalogs.load_cancellation_reasons)

catalogs.load_exception_reasons: Breakdown — roadside · Breakdown — towed to shop · Accident / incident · Weather / road closure · Border / customs hold · Detention at shipper / receiver · Layover · Driver rest / HOS · Reroute / new appointment · Load cancelled by customer · Other (note required). Each row: name, applies_to, linked module, active flag; owner may add rows from Lists without code. The dropdown in the pop-up lists them visibly (not a hidden select) so the reason is chosen by name.

Rules

1. Forward only, one station at a time, via the same state machine as the Kanban drop; refused = server reason on the node, never silent. 2. Every stamp stores time, actor, evidence; hover shows all three. 3. No-ping = red “No ping — last position unavailable”, never blank. 4. Late = appointment passed with no arrival stamp — orange, appointment shown. 5. Multi-stop loads add one “At stop n” node per extra stop. 6. Team loads: both drivers on the card, one row per truck. 7. Gear / sort / density exactly like the Load Costs board (ParityTable). 8. Colors: the app's own palette everywhere; the line alone is green (reached) / red (issue). No station colors.
