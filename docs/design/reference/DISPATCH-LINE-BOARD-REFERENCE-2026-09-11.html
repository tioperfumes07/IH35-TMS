Design contract — Dispatch › Line Board (owner request 2026-09-11 16:30 CT)

Owner, verbatim: “a new kanban format design page almost the same as it is here. but it will be instead of dragging the truck box, it will be like a line map of a truck … when we double click on that rows box, for instance if we have a load on T122, we input all data etc. we double click on dispatch, and it shows the line and that it is currently at dispatched, we then click on at pick up etc.” Follow-up: “we are missing in the design the status names on top.” → station names are the column header, aligned to the nodes.

What it is

The Kanban's data, one row per truck, no dragging. Every truck gets ONE row for as long as it is in service. The row shows the truck's current load and a horizontal line of stations under the station-name header. The line fills to the station the load has reached; the next station is the only clickable advance; clicking it stamps the real event on the real row (never a free-text status). Double-clicking the truck box opens the load page (Accounting › Load costs › <load>, the LDT-PAGE route). Additive — the Kanban stays; this is a 4th segment in the same List | Kanban | Line Board | Round Trips control.

Rules

1. Stations advance only forward, one at a time, by the same state machine the Kanban drop uses; a refused transition shows the server's reason on the node, never a silent no-op. 2. Every stamp records time, actor and evidence source; the hover tip shows all three. Nothing is inferred from a GPS ping without saying so. 3. A truck with no load renders the row with a grey rail and “Book Load on Txxx” — a row is never dropped because it is empty (additive-only). 4. Live position column reads telematics.vehicle_latest_position; no ping = “No ping — last position unavailable” in red, never a blank. 5. Late vs appointment = now() > appointment with no arrival stamp — amber, with the appointment time shown. 6. Multi-stop loads: the line adds one “At stop n” node per extra stop between pickup and delivery. 7. Team loads: both drivers on the card; one row per truck, not per driver. 8. Sorting: Unit (default), Driver, Customer, Next appointment; the gear controls columns exactly like the Load Costs board (ParityTable). 9. Density toggle Compact 32px / Standard 44px rows.
