=== IMPORT-3v2 — OPENING BALANCE ENGINE (supersedes v1's full-TB approach — OWNER-ACCEPTED RECOMMENDATION) ===

WHY BALANCE-SHEET-ONLY (locked rationale, do not re-open): the QBO Balance Sheet as of 12/31/2023 already contains all 2023-and-prior P&L inside its Retained Earnings line (QBO computes the fiscal close). Importing the full trial balance would bring 2023 P&L account balances into the TMS and require the TMS to re-derive a 2023 year-end close — a dependency and a double-count risk. Balance-sheet-only is the QuickBooks/NetSuite conversion standard: opening position = balance sheet accounts (incl. RE); P&L truth begins at the 01/01/2024 detail import.

ENGINE — apps/backend/src/integrations/qbo/import/opening-balance.service.ts:
1. runOpeningBalanceImport(opco): realm↔opco assert (unrevoked connection only), per-opco advisory lock, refuse unless IMPORT-P0 flag/gates verified present in code at runtime (probe the refusal path exists — belt and suspenders), refuse unless entity COA sync is complete (TRK: equity acceptance list present).
2. Pull QBO **BalanceSheet report** as of 2023-12-31, accounting_method='Accrual', per entity, via qboReport + a parseBalanceSheet added to the parser module (leaf-account rows only — parse the Rows tree to leaf ColData with qbo account ids; section summaries are validation, not import rows). Assert QBO's own equation to the cent: TotalAssets = TotalLiabilities + TotalEquity from the report summaries.
3. HOME CURRENCY: read the entity home currency (CompanyInfo or connection metadata — verify source, no guess). Every parsed line must be home-currency; if the report exposes any non-home-currency structure or IMPORT-1v2 flagged foreign-currency accounts with balances → ABORT with the list. FX opening treatment is an owner decision that has not been made; do not invent one.
4. Map every leaf line to catalogs.accounts by (opco, qbo_account_id) — INCLUDING inactive accounts (IMPORT-1v2 synced them; account_active_at_source recorded on the tieout row). ANY unmatched line = abort with the full unmatched list; fix path = re-run COA sync.
5. Compose ONE balanced opening JE per entity: entry_date 2023-12-31, source_system='qbo_import', source='qbo_opening_balance_sheet', qbo_sync_pending=false, deterministic idempotency_key 'qbo-opening-bs:{opco}:2023-12-31'. Lines: each balance-sheet account on its natural signed side (Retained Earnings included as QBO reports it). The entry balances BY CONSTRUCTION; assert residual = 0 cents. IF a nonzero residual ever appears (rounding/report anomaly): post the residual line to the entity's Opening Balance Equity account, mark the run 'variance', and create a visible follow-up record "OBE residual {amount} — owner reclass OBE→Retained Earnings required". OBE is a TEMPORARY CLEARING account only — a permanent OBE balance is a defect, never an outcome.
6. Idempotent re-run (QBO 2023 balances can shift during the cleanup): upsert on idempotency_key — atomically replace the entry's postings, version_int++, audit row per run (created/replaced + variance). A re-run also marks all later GL-detail runs/tieouts for the entity STALE (forward invalidation — see IMPORT-4v2).
7. Set opening_balance_cents + opening_balance_as_of='2023-12-31' on balance-sheet accounts from the report (same txn). P&L accounts get NO opening balance (by design).
8. Cash mirror: same run pulls TrialBalance as of 2023-12-31 accounting_method='Cash' → accounting.qbo_cash_basis_balances upsert (report data for the cash-basis financials during the QBO-SoR window; unmatched rows land matched=false, logged loudly, do not abort the accrual JE).
9. Tieout rows per account (leaf-level, signed): qbo_balance_cents vs tms_balance_cents; nonzero variance → run 'variance', loud failure. Owner-triggered only ('qbo.import.opening_balance').
