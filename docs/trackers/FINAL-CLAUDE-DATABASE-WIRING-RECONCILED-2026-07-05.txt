## PART 1 — LIVE FINDINGS (from the introspection map)
- **[HIGH]** public.audit_log + 48 monthly partitions have NO RLS at all — Audit data readable by any DB role that can reach the schema. Correct: RLS FORCED like audit.audit_events, or lock grants to a single writer role.
- **[HIGH]** events.event_log (the immutable hash-chained audit log) has RLS but NOT FORCED — The table owner can bypass RLS — on the tamper-evidence log itself. Correct: FORCE ROW LEVEL SECURITY (one-line migration).
- **[HIGH]** Entire insurance schema (8 tables) has NO operating_company_id — Policies/claims/COIs are not entity-separated — TRK's insurance and TRANSP's insurance blend. Violates entity independence. Correct: add opco + per-entity RLS (part of the known ~16-endpoint leak fix, pre-USMCA).
- **[HIGH]** Entire factoring schema (batch, factor, reserve_movement, customer_factor_assignment) has NO operating_company_id — Factoring is TRANSP-only today so it works by accident — the moment a second entity factors, data blends. Correct: opco + per-entity policies before any second-entity factoring.
- **[MED]** mdata.units, mdata.equipment, mdata.assets have NO operating_company_id — Trucks are TRK-owned, TRANSP-operated — ownership vs operation is not expressible. Known cross-entity leak class; must be resolved before USMCA.
- **[MED]** Three outbox tables exist: outbox.events (30,782 rows, NO RLS), outbox.outbox_queue (0 rows, NO RLS), outbox.queue (RLS ok) — Two generations of the same mechanism plus one live one. Correct: confirm the single live path in code, archive the legacy two, add RLS or drop.
- **[MED]** Four settlement families: settlement.*, settlements.*, driver_finance.driver_settlements, payroll.driver_settlements — driver_finance.escrow_ledger still FKs into settlement.settlement — the old family is still wired into live escrow. Correct: one canonical family, others voided/archived with FKs repointed.
- **[MED]** Twin schemas from drift: maint vs maintenance, factor vs factoring, master_data vs mdata, docs vs documents, geo vs geofence, qbo vs qbo_sync — Each pair splits one domain across two homes; agents guess wrong. Correct: declare canonical per pair in MULTI-ENTITY/architecture doc + migrate stragglers.
- **[MED]** safety.civil_fines has no voided_at (internal_fines has it) — A wrongly-entered civil fine can only be deleted or edited — breaks void-never-delete on a money-adjacent record. Correct: add voided_at (additive migration).
- **[LOW]** maintenance.work_order_lines + wo_status_history have NO RLS — Work-order money lines unprotected. Correct: enable+force RLS like sibling tables.
- **[LOW]** 41 tables are FK islands (0 out, 0 in) — mostly caches/logs/ledgers, but each was reviewed in ALL TABLES verdicts — Islands are fine for caches; not fine for business records. The verdict column marks which is which.
- **[LOW]** identity.email_verifications, sms.queue, whatsapp.queue, shipper_portal sessions/tokens: NO RLS — Token/queue tables — low blast radius but inconsistent with the standard. Correct: enable RLS or document the exception.
