## 4. THE FIX — the engine, three parts, all required

### (a) A reversal line is terminal. Refuse at the writer.

In the void/reversal path, before emitting a reversal for a line:

```
if (line.reversal_of_line_id !== null) throw new Error("posting_line_is_already_a_reversal");
```

Refuse **by name**, in `apps/backend/src/governance/void-cancel-executors.ts` and anywhere else that
emits a reversal. This is the root fix — everything else below is containment.

### (b) Find out why the document-level idempotency did not stop it.

CC-2's 393.3 rehearsal reported *"A second void reversed nothing"* on `EXP-2026-00001`. Good — so a
document-level guard exists. **But these 60 happened anyway**, on 09-30, which means either the guard
landed after 09-30, or the path that produced them bypasses it. **Determine which and say so.** If
the purge path calls the reversal writer directly instead of going through the document void, that is
the hole, and the purge engine you are building in ROUND 390 must not have it.

### (c) The guard — a live, zero-tolerance assertion

No posting may have `reversal_of_line_id` pointing at a line that itself has
`reversal_of_line_id IS NOT NULL`:

```sql
SELECT count(*) FROM accounting.journal_entry_postings p
  JOIN accounting.journal_entry_postings t ON t.id = p.reversal_of_line_id
 WHERE t.reversal_of_line_id IS NOT NULL;
-- must be 0
```

Today that returns **60**. Wire it as a live step. Selftest must FAIL on a planted three-deep chain
and PASS on original→reversal. **No baseline, no allowlist** — a double reversal is never acceptable,
so there is nothing to ratchet down from.
