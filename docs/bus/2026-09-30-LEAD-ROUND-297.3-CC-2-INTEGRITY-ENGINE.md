## MEASURED LIVE — the attribution spine EXISTS

`telematics.vehicle_driver_assignments` (USMCA): 617 assignments · 45 drivers · 15 units · 8 open
right now. started_at 2026-05-14 -> 2026-09-30 · 2 distinct sources. Columns: unit_id, driver_id,
started_at, ended_at, source, is_default. That table is the answer to "he wasn't in that truck."
Every attribution resolves the driver by the assignment window CONTAINING the event timestamp —
never by `mdata.units.assigned_driver_id`, which is only who is in it TODAY.

## B-27 — THE ATTRIBUTION FUNCTION — ONE, SHARED

- FILE `apps/backend/src/maintenance/driver-attribution.ts` (NEW)
- EXPORT `driverAtTimeSql(unitAlias, tsExpr)` -> the lateral join every metric uses.
- RULE a single definition. Nine copies of a predicate is how the severe-repair bug happened
  (measured: one allowlist pasted into 9 sites, all 9 wrong). Do not inline this join.
- GAP an event with no covering assignment resolves to NULL driver and is COUNTED AS
  UNATTRIBUTED in its own bucket. Never dropped, never assigned to the nearest driver.

## B-28 — FUEL / MPG PER DRIVER

- INPUT `fuel.fuel_transactions` (177 live USMCA rows, ALL source='import', last 2026-09-24
  07:09 CT) + `telematics.odometer_readings` (CC-3 builds the ledger, ROUND 297.1).
- METRIC per driver per period: gallons, miles driven under his assignments, MPG, gal/100mi,
  $/mile, and fills carrying NO load link.
- FLAG the theft signal, stated plainly, never as an accusation:
  - MPG > 1.5 SD BELOW fleet mean over 30+ days
  - a fill whose gallons exceed the unit's tank capacity
  - two fills inside 90 minutes more than 50 miles apart
  - gallons bought exceeding miles / fleet-worst MPG for the window
  Each flag names the exact transactions behind it, and the payload itself says a flag is
  evidence to look at.
- BAR never compute MPG from estimated mileage. An odometer gap over the window returns MPG
  NULL with reason='odometer_gap'. Never interpolate fuel math.

## B-29 — DAMAGE / TIRE / ACCIDENT PER DRIVER

- INPUT `maintenance.work_orders` (severity, wo_type='accident', vmrs), `maintenance.tire_events`,
  `maintenance.driver_reports`, safety accident records, insurance claim linkage.
- METRIC per driver: accidents, damage WOs, tire events, $ caused, down-days caused — AND the
  same figures per 100,000 miles HE drove. A raw count would libel the hardest worker in the
  fleet.
