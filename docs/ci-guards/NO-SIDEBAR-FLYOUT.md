# No-Sidebar-Flyout Guard

**Script:** `scripts/verify-no-sidebar-flyout.mjs` — **npm:** `npm run verify:no-sidebar-flyout` — **runs in:** the `verify:arch-design` chain (CI).

Jorge's locked navigation design (§7) is one 80px navy sidebar (`components/Sidebar.tsx`, `rgb(27,35,51)`) as the sole left panel — no second panel, no accordion left tree, and no hover-triggered flyout submenu off it. A `SidebarFlyoutMenu.tsx` component implementing exactly that forbidden hover-flyout pattern has been built and removed **twice** (each time because a bespoke, spec-matching pattern was already live elsewhere), so this guard exists to make a third silent re-add fail CI instead of drifting back into the repo unnoticed. It checks two things: (A) no `.ts`/`.tsx` file under `apps/frontend/src` (excluding `*.test.*`/`*.stories.*`) has a basename matching `SidebarFlyout` or `FlyoutMenu`, and (B) the single live sidebar file itself, `components/Sidebar.tsx`, contains no reference to "flyout" and imports no module whose path contains "flyout" — scoping check B to that one file (rather than a repo-wide keyword scan) keeps the guard precise and avoids false positives on legitimately-named, unrelated hover/flyout UI elsewhere in the app (e.g. the reports category hover-nav or the lists domain flyout), which are not the sidebar and are not restricted by this rule.
