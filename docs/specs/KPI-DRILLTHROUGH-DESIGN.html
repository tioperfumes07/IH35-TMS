IH35 — KPI drill-through specification

Every KPI that counts units, loads or transactions opens a real columned table. No KPI opens a page that shows something other than what it counted, and no KPI is a dead number. This file is the build spec: the tables below are the columns, in order, with the required states. Palette follows design-tokens.css — no purple, blue or pink, no emoji.

The defect this replaces. Today the maintenance row renders seven bare tiles with no section heading and no captions, so the operator cannot tell whether they count units or work orders (they count work orders). And the dispatch overview computes atRiskLateTotal = atRiskCount + lateCount, double-counting any load that is both, then drills to /dispatch/at-risk which shows only half of what the tile counted.

1 · The KPI tile — required anatomy

Work orders — open, all statuses except closed Source: maintenance.work_orders · live
Required on every tile.
1. A section heading bar naming what the whole row counts and its time window.
2. A label, uppercase, 11px.
3. The value, tabular numerals, semantic colour only when it means attention.
4. A caption stating the exact rule and threshold, read from the service — never invented.
5. The whole tile is a button. A KPI that does not click is a defect.
6. The selected tile shows a 2px inset ring, not a colour tint alone.
The counting law. The number on the tile and the row count of the table it opens must be identical. If a load is both at-risk and late it is counted once. Before you ship any tile, assert tile.value === drill.rowCount in a test. A tile that disagrees with its own drill-through is a lie on the owner's screen.

The "No JE" chip is not decoration. Three documents in this system currently claim POSTED with zero journal entries. The chip is how the operator sees that on the same screen as the money, instead of finding it at period close.

5 · Rules that bind every drill-through

ParityTable only. Every table above is a ParityTable — it inherits drag-resize, drag-reorder, auto-fit, the gear and the standard header. Do not hand-roll a <table>. Forty-six screens already did and none of them can be resized.
Server-side sort and filter. The header sort must re-query. Sorting the 100 rows already fetched gives the operator the wrong answer on any longer list.
Real date range. The range control must re-query, not filter rows in memory. "Late arrivals last Tuesday" has to be answerable.
Every identifier is a link. Unit, load, driver, invoice, JE. A number the operator cannot click is a dead end.
Money is right-aligned, tabular, two decimals. Variance is red when non-zero and never hidden.
Empty state names the filter. "No loads at risk in the selected range" — never a blank panel.
Ship gate. For each KPI paste: the tile value, the drill row count, and a live screenshot showing them equal. If they differ, the KPI is the bug — do not adjust the table to match it.
