## Owner ruling (2026-07-24)
> "lists and catalogs should be per entity, but we use the same catalog for all entities."

Each entity OWNS its own catalog rows (so USMCA/TRK can diverge later if ever needed), but IH35 seeds **identical** values to every entity today. This is the **first** of the LST per-entity conversions.

## What this converts
8 GLOBAL fleet/asset reference catalogs → per-entity, matching the already-per-entity dispatch catalogs (`catalogs.load_types`):
`asset_condition_codes, asset_locations, asset_statuses, unit_ownership_types, trailer_types, lease_terms, tractor_statuses, trailer_statuses`.

## Migration `202607860000` (HELD — owner Neon-applies)
- add `operating_company_id`; **backfill existing rows → TRANSP** so no existing reference moves (these 8 have **zero inbound FKs** — verified on prod);
- **COPY** the TRANSP rows to USMCA + TRK with fresh PKs (same values → "same catalog for all"; `ON CONFLICT (operating_company_id, code) DO NOTHING`);
- swap `UNIQUE(code)` → `UNIQUE(operating_company_id, code)`;
- `ENABLE` + `FORCE` RLS with the standard GUC `company_scope` policy the factory's `set_config` feeds (identical to `load_types`);
- `REVOKE DELETE` (void-not-delete);
- **harmonize `created_by_user_id`/`updated_by_user_id`** onto the 4 tables that lacked them — the shared fleet factory POST wrote those columns and **500'd on those 4 → 0 rows**; this fixes that latent create-500.

## Backend
`fleet/factory.ts` is now config-driven (`companyScoped`): the 8 run every read/write under `withCompanyScope` (membership + `app.operating_company_id` GUC + RLS) and scope `code`-uniqueness per entity. The lists count spec + scoping test flip the 8 to `companyScoped:true`.
